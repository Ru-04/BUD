# BUD — your all-time buddy

Voice-first, English/Hinglish conversational companion for the AI Build Challenge 2026. BUD classifies the user's conversational need, applies response rules and user-controlled personality preferences, and asks before saving long-term memories.

## Status

Gate 1 has a React/Vite app shell and FastAPI health endpoint. Gate 1 is verified: backend tests, the frontend render smoke test, local HTTP checks and the production build pass; the user confirmed browser rendering, no console errors, Backend connected and a 360px layout without overlap or horizontal scrolling. Gate 2 (typed chat, Groq integration on `openai/gpt-oss-120b`, five-mode safety-first analyzer, and a consistent warm/curious/humour-capable personality layer) is **verified complete**, including live browser acceptance. Gate 3 (SQLite persistence, per-visitor isolation, four personality sliders, and the propose/approve/reject/delete memory flow) is **verified complete**, including a user-reported personality-conditioning bug found, root-caused and fixed, then confirmed live in the browser. Gate 4 (browser microphone recording, Groq Whisper transcription, shared chat path, a full-page voice-first redesign, and BUD speaking its replies) is **implemented and partly verified**, with two rounds of user-reported live bugs found and fixed: a Hinglish transcription hallucination (missing decoder context, fixed via Groq's real `prompt` parameter) and a genuine `React.StrictMode` race condition where "pause" left an orphaned microphone recorder running uncontrolled. The permanent sidebar was replaced with a central animated `BudOrb` (now with an entrance animation), a floating Write/Let's-talk/Parameters action band, a real waveform recording panel with working pause/resume, on-demand overlays for Parameters and account settings, and BUD now speaks each reply aloud via Groq's Orpheus TTS (muteable) — all preserving BUD's existing palette/theme/personality/memory untouched. 190 backend tests and 18 frontend tests (including a new jsdom+RTL interaction-test harness) pass. Outstanding before Gate 4 closes: the user's own live retest of Hinglish transcription and the pause fix, and the TTS voice engine's one-time Groq-console terms acceptance (a manual, login-gated step only the account owner can complete) before spoken replies can be verified at all. Premium Dribbble-level visual polish is not implemented yet (Gate 5+). See `docs/deployment.md` for executable local commands and `tasks.md` for evidence.

## Start here

1. Review the open decisions in `docs/scope.md` before dependent later gates. They do not block local Gate 1. Add a screenshot of the exact Dribbble shot for layout fidelity.
2. Read `CLAUDE.md`, `skill.md`, `docs/technical-scope.md`, `docs/architecture.md`, `docs/api-contracts.md`, and `docs/ui-direction.md`.
3. Complete gates in `docs/build-plan.md` in order; update `docs/sprint-tracker.md` with proof and mark `tasks.md` as evidence is produced.
4. Gate 1 needs no secrets. Gate 2 loads server-only Groq settings from ignored `backend.env` (or `backend/.env`); see `docs/deployment.md`. Optional public frontend configuration is in `frontend/.env.example`; never put secrets there.

Do not claim a feature works until its acceptance checks pass. The UI adapts the documented palette and visual principles; it is not an exact Dribbble match.
